## 一、业务规则说明

系统中的 `custom_templates` 现在分为两类：

1. 公共模板
   - 由 `GY_homeQuality` 的 admin 端统一维护
   - `template_scope = 1`
   - 可以设置关联的大模型模板、科室、病种、文书类型、状态

2. 用户模板
   - 由 `GY_bazb` 前台用户基于公共模板进行“个人编辑”产生
   - `template_scope = 2`
   - 通过 `source_template_id` 关联公共模板
   - 前台不能新增公共模板，只能编辑自己的个人模板

前台列表逻辑：

- 先查公共模板
- 再查当前 `staff_code` 下是否存在对应公共模板的个人模板
- 如果存在，则列表中用个人模板覆盖公共模板
- 如果不存在，则直接返回公共模板

示例：

- 公共模板有 `1`、`2`
- 当前用户只编辑过公共模板 `2`
- 那么前台返回：
  - 公共模板 `1`
  - 用户自己的模板 `2`

### 2. 获取公共/个人模板列表

#### 接口地址

```text
GET /bazb/big_model/custom_template_list
POST /bazb/big_model/custom_template_list
```

#### 请求参数

| 参数名 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `big_model_template_id` | int | 否 | 关联大模型模板ID |
| `department_id` | int | 否 | 科室ID，用于排序优先展示匹配科室的模板，不作为强过滤 |
| `disease_id` | int | 否 | 病种ID，用于排序优先展示匹配病种的模板，不作为强过滤 |
| `staff_code` | string | 否 | 当前登录人工号，传了才会执行“个人模板覆盖公共模板”逻辑 |
| `page` | int | 否 | 页码，默认 `1` |
| `page_size` | int | 否 | 每页数量，默认 `10` |

#### 排序说明

- `big_model_template_id` 仍作为过滤条件。
- `department_id`、`disease_id` 不会过滤掉其它模板，只影响排序。
- 只传 `disease_id` 时，匹配该病种的模板优先展示。
- 只传 `department_id` 时，匹配该科室的模板优先展示。
- 同时传 `department_id` 和 `disease_id` 时，排序优先级为：
  1. 病种匹配
  2. 科室匹配
  3. 模板ID倒序

```json
{
  "big_model_template_id": 1,
  "department_id": 2,
  "disease_id": 3,
  "staff_code": "10001",
  "page": 1,
  "page_size": 10
}
```

### 3. 编辑个人模板

说明：

- 前台不能新增公共模板
- 如果传入的是公共模板ID，则系统会为当前 `staff_code` 新建一条用户模板
- 如果传入的是当前用户自己的用户模板ID，则系统会直接更新该用户模板

#### 接口地址

```text
POST /bazb/big_model/edit_custom_template
```

#### 请求参数

| 参数名 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `id` | int | 是 | 模板ID，可以是公共模板ID，也可以是当前用户自己的用户模板ID |
| `name` | string | 否 | 模板名称，不传则沿用公共模板名称 |
| `content` | string | 是 | 编辑后的模板内容 |
| `document_type` | string | 否 | 文书类型，不传则沿用公共模板或基础模板的文书类型 |
| `staff_code` | string | 是 | 当前用户工号 |
| `staff_name` | string | 否 | 当前用户姓名 |

#### 请求示例

```json
{
  "id": 2,
  "name": "肺炎病历模板-张三",
  "content": "这是张三自己调整后的模板内容。",
  "document_type": "入院记录",
  "staff_code": "10001",
  "staff_name": "张三"
}
```


### 6. 病历生成

#### 接口地址

```text
POST /bazb/big_model/generate_medical_record
```

#### 请求参数

| 参数名 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `content` | string | 是 | 病史描述内容 |
| `template_id` | int | 是 | 大模型模板ID |
| `custom_template_id` | int | 否 | 自定义模板ID，建议传前台列表中最终展示的那条模板ID |

#### 说明

- 如果 `custom_template_id` 是公共模板ID，则只会使用公共模板内容
- 如果 `custom_template_id` 是当前用户模板ID，则会使用该用户编辑后的模板内容
- 生成时，系统会把自定义模板内容拼接到大模型模板后面

```json
{
  "code": 200,
  "data": {

    "custom_template_id": 12,
    "custom_template_name": "肺炎病历模板-张三",

    "generate_date": "2026-05-08 15:30:20",
```

## 四、完整业务流程

### 场景1：后台新增公共模板，前台用户个性化编辑

```text
1. admin端新增公共模板
2. 前台调用 custom_template_list 拉取公共模板
3. 用户选择某个公共模板进行编辑
4. 前台调用 edit_custom_template
5. 系统生成一条关联 source_template_id 的用户模板
6. 前台再次拉列表时，该模板由用户模板覆盖展示
7. 生成病历时传 custom_template_id
```

### 场景2：前台直接用公共模板生成

```text
1. 工号验证
2. 拉模板列表
3. 未进行个性化编辑
4. 直接用公共模板ID生成病历
```

### 场景3：语音输入生成病历

```text
1. 工号验证
2. 调用 audio_transcription 转写
3. 选择模板
4. 调用 generate_medical_record 生成病历
5. 调用 save_medical_record 保存
```

## 五、错误码说明

| 错误码 | 说明 |
| --- | --- |
| `200` | 成功 |
| `4001` | 参数缺失或当前操作不允许 |
| `4002` | 数据不存在或工号缺失 |
| `4003` | 模板内容为空或未找到模板 |
| `4004` | 未找到对应模板/配置 |
| `4005` | 只能编辑自己的模板 |
| `500` | 服务器内部错误 |

## 六、注意事项

1. 前台 `create_custom_template` 已不再用于新增公共模板。
2. 公共模板必须在 admin 端维护。
3. 前台编辑公共模板时，本质上是生成一条用户模板覆盖记录。
4. 生成病历时若传入的是用户模板ID，则优先使用用户模板内容。
5. 前台模板列表中 `department_id`、`disease_id` 用于排序优先展示匹配模板，不会过滤掉其它模板；后台公共模板列表仍可按科室、病种筛选。
6. 文书类型统一使用 `document_type` 字段传递和返回。
