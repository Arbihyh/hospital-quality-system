# 门诊病历质控接口说明

## 环境配置

### 数据库连接配置

门诊数据库连接信息存储在 `SJK_CONN` 表中，`SJK_ID = 10` 为门诊数据库连接。

#### 配置表结构
```sql
CREATE TABLE `SJK_CONN` (
    `SJK_ID` int(11) NOT NULL AUTO_INCREMENT COMMENT '数据库连接ID',
    `SJKLX` varchar(50) DEFAULT NULL COMMENT '数据库类型：ORACLE/SQL_SERVER/MYSQL',
    `host` varchar(100) DEFAULT NULL COMMENT '主机地址',
    `port` int(11) DEFAULT NULL COMMENT '端口',
    `username` varchar(50) DEFAULT NULL COMMENT '用户名',
    `password` varchar(100) DEFAULT NULL COMMENT '密码',
    `database` varchar(50) DEFAULT NULL COMMENT '数据库名称',
    PRIMARY KEY (`SJK_ID`) USING BTREE
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='数据库连接配置表';
```

#### 配置示例

**Oracle 数据库配置：**
```sql
INSERT INTO SJK_CONN (SJK_ID, SJKLX, host, port, username, password, database) 
VALUES (10, 'ORACLE', '172.16.9.8', 1521, 'zdyh', 'zdyh', 'his');
```

**MySQL 数据库配置：**
```sql
INSERT INTO SJK_CONN (SJK_ID, SJKLX, host, port, username, password, database) 
VALUES (10, 'MYSQL', '127.0.0.1', 3306, 'root', 'password', 'his_db');
```

**SQL Server 数据库配置：**
```sql
INSERT INTO SJK_CONN (SJK_ID, SJKLX, host, port, username, password, database) 
VALUES (10, 'SQL_SERVER', '192.168.1.100', 1433, 'sa', 'password', 'his_db');
```

**注意**：SQL Server 连接使用 `SqlServerProxyService`，需要确保：
1. SQL Server 代理服务已启动
2. 在 `.env` 中配置代理服务地址：
   ```env
   SQLSERVER_PROXY_URL=http://sqlserver-proxy:8080/api/sql
   SQLSERVER_PROXY_TIMEOUT=30
   ```

## 接口地址
```
POST /api/quality_handle_mz
```

## 请求参数

| 参数名 | 类型 | 必填 | 说明 |
|--------|------|------|------|
| MZID | string | 否 | 门（急）诊代码，目前用BLBH替代 |
| BLBH | string | 是 | 病历编号 |
| BLMC | string | 否 | 病历标题名称 |
| BLZT | string | 是 | 病历状态：1.完成；2.封存(归档)；3.草稿；9.删除 |
| MZHM | string | 否 | 门诊号码 |
| JZXH | string | 否 | 就诊序号 |
| BRBH | string | 否 | 病人编号 |
| BRXM | string | 否 | 病人姓名 |

## 请求示例

```json
{
    "MZID": "F1457",
    "BLBH": "66ab6cd96ae44a6976dfc8f2",
    "BLMC": "门诊病历",
    "BLZT": "1",
    "MZHM": "F123456",
    "JZXH": "JZ202401001",
    "BRBH": "123123",
    "BRXM": "张三"
}  
```

## 返回结果

### 成功响应
```json
{
    "code": 200,
    "msg": "质控完成",
    "data": {
        "MZID": "F1457",
        "req": 1,
        "sftc": 1
    },
    "time": 1714408550
}
```

### 字段说明

| 字段名 | 类型 | 说明 |
|--------|------|------|
| code | int | 响应状态码：200表示成功，4001表示请求参数有误 |
| msg | string | 响应信息：描述性文字 |
| data.MZID | string | 门（急）诊代码 |
| data.req | int | 必改问题数量（强制问题）：0表示无强制问题；非0表示存在强制问题。规则：rule_id<1000000 查询 omr_rule 表，rule_id>=1000000 查询 rule_setting 表（通过 rule_setting.id + 1000000 = rule_id 关联），error_level=1 为强制，error_level=2 为建议 |
| data.sftc | int | 是否弹窗：1.代表有缺陷问题，可弹窗；0.代表得分是100分，可不弹窗 |
| time | int | 响应时间戳 |

## 处理流程

### 1. 删除病历（BLZT=9）
- 删除 `omr_bl01` 表中的病历数据
- 删除 `omr_quality` 表中的质控结果
- 删除 ES 索引中的相关数据

### 2. 正常质控流程（BLZT≠9）

#### 2.1 数据同步
根据 `rulewordmap` 表中配置的 SQL 语句同步以下数据：

- **omr_bl01**：门诊病历基础数据
  - 配置名称：`omr_bl01_sql`
  - 参数：`:BLBH`, `:JZXH`, `:BRBH`, `:MZHM`

- **omr_blsy**：病历签名数据（可能多条）
  - 配置名称：`omr_blsy_sql`
  - 参数：`:BLBH`
  - 注意：会先删除旧记录，再插入新记录

- **jzls**：就诊流水数据
  - 配置名称：`jzls_sql`
  - 参数：`:JZXH`, `:BRBH`

- **brda**：病人档案数据
  - 配置名称：~~`brda_sql`~~（已废弃，改为直接使用传入参数）
  - 参数：`BRBH`（病人编号）、`BRXM`（病人姓名）、`MZHM`（门诊号码）
  - 说明：直接使用接口传入的参数更新或插入 `ms_brda` 表，字段映射：
    - `BRID` = `BRBH`
    - `BRXM` = `BRXM`
    - `MZHM` = `MZHM`

#### 2.2 数据格式化
调用 `MzBlDataFormatService::formatBlData()` 方法对病历内容进行格式化处理

#### 2.3 执行质控
调用 `OmrQualityCommand::omrZk()` 方法执行质控规则检查

#### 2.4 返回结果
- 查询病历得分
- 统计必改问题数量（强制问题）
  - **rule_id < 1000000**：查询 `omr_rule` 表，`error_level=1` 为强制问题
  - **rule_id >= 1000000**：查询 `rule_setting` 表（通过 `rule_setting.id + 1000000 = rule_id` 关联），`error_level=1` 为强制问题
  - `error_level=2` 为建议问题
- 判断是否需要弹窗提醒

## 配置说明

需要在 `rulewordmap` 表中配置以下 SQL 语句：

### 1. omr_bl01_sql（根据 BLBH 查询）
```sql
SELECT * FROM omr_bl01_source 
WHERE BLBH = :BLBH
```

### 2. omr_blsy_sql（根据 BLBH 查询，可能多条）
```sql
SELECT * FROM omr_blsy_source 
WHERE BLBH = :BLBH
```
**注意**：
- 此表可能返回多条签名记录
- 同步时会先删除旧记录（根据 BLBH），再批量插入新记录

### 3. jzls_sql（根据 JZXH 查询）
```sql
SELECT * FROM ys_mz_jzls 
WHERE JZXH = :JZXH
```

### 4. brda_sql（根据 BRID 查询）
```sql
SELECT * FROM ms_brda 
WHERE BRID = :BRBH
```

## 唯一标识说明

| 表名 | 查询条件 | 说明 |
|------|---------|------|
| omr_bl01 | BLBH | 病历编号（唯一） |
| omr_blsy | BLBH | 病历编号（一个病历可能有多条签名记录，先删除再批量插入） |

## 错误码说明

| 错误码 | 说明 |
|--------|------|
| 200 | 成功 |
| 4001 | 请求参数有误（如：病历编号为空、病历不存在） |
| 500 | 服务器内部错误 |

## 注意事项

1. **BLBH 必填**：病历编号是必须参数
2. **BLZT=9 特殊处理**：删除状态会清空所有相关数据
3. **多条签名记录**：omr_blsy 可能有多条签名记录，会先删除后插入
4. **SQL 配置**：确保 rulewordmap 表中配置了正确的 SQL 语句
5. **日志记录**：所有操作都会记录日志，便于排查问题
6. **数据库连接配置**：
   - 连接信息存储在 `SJK_CONN` 表中
   - `SJK_ID = 10` 为门诊数据库连接
   - 支持 Oracle、MySQL、SQL Server 三种数据库
   - 通过 `SJKLX` 字段指定数据库类型
   - SQL Server 需要配置代理服务（`SqlServerProxyService`）
7. **Oracle 参数占位符**：在 SQL 中使用 `:参数名`，不要加引号
8. **MySQL 参数占位符**：在 SQL 中使用 `':参数名'`，需要加引号
9. **必改问题统计规则**：
   - **rule_id < 1000000**：从 `omr_rule` 表查询，`error_level=1` 为强制问题
   - **rule_id >= 1000000**：从 `rule_setting` 表查询（通过 `rule_setting.id + 1000000 = rule_id` 关联），`error_level=1` 为强制问题
   - `error_level=2` 为建议问题，不计入必改数量
   - 关联逻辑：`omr_quality.rule_id = rule_setting.id + 1000000`
