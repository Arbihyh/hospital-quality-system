# 质控报告下钻接口文档

> 基础路径：`/api/quality_report/quality_report_drill`

---

## 公共请求参数

三个接口的请求参数**完全一致**，均为 POST 请求，Content-Type: `application/json`。

| 参数名 | 类型 | 必填 | 说明 |
|--------|------|------|------|
| discharge_date_start | string | 否 | 出院日期起始，支持 `20260101`|
| discharge_date_end | string | 否 | 出院日期截止，支持 `20260131`|
| discharge_departments | array | 否 | 出院科室，多选，如 `["科室A","科室B"]` |
| case_number | string | 否 | 病案号，精确匹配 |
| admission_departments | array | 否 | 入院科室，多选 |
| admission_date_start | string | 否 | 入院日期起始，格式同出院日期 |
| admission_date_end | string | 否 | 入院日期截止，格式同出院日期 |
| campus | array | 否 | 院区代码，多选 |
| record_levels | array | 否 | 病历等级筛选，如 `["甲","乙","丙"]` |
| patient_status | string | 否 | 患者状态：`在院` / `出院` / `全部` |
| catalog_status | string | 否 | 编码状态：`已编目` / `未编目` / `全部` |
| is_danfou | string | 否 | 是否有单否问题：`有` / `无` / `全部` |
| resident_doctor | array | 否 | 住院医师代码（AEE04_CODE），多选 |
| page | int | 否 | 页码，默认 `1` |
| limit | int | 否 | 每页条数，默认 `20` |

---

## 公共响应结构

```json
{
  "code": 0,
  "msg": "",
  "data": {
    "total": 100,
    "page": 1,
    "limit": 20,
    "list": [...]
  }
}
```

## 一、质控病历数下钻

**POST** `/totalCasesDrillDown`

查询所有病历记录，按出院日期倒序，每个患者一条记录。

### 响应 list 字段

| 字段名 | 类型 | 说明 |
|--------|------|------|
| name | string | 患者姓名 |
| age | string | 年龄 |
| case_number | string | 病案号 |
| record_grade | string | 病历等级（甲/乙/丙） |
| record_grade_score | number | 等级总分（事中+首页） |
| case_score | number | 事中得分（满分80） |
| home_score | number | 首页得分（满分20） |
| admission_date | string | 入院日期 |
| admission_department | string | 入院科室 |
| admission_ward | string | 入院病区 |
| discharge_date | string | 出院日期 |
| discharge_department | string | 出院科室 |
| discharge_ward | string | 出院病区 |
| hospital_days | string | 住院天数 |
| admission_status | string | 入院时情况 |
| diagnosis_code | string | 出院诊断ICD（前3位） |
| diagnosis_name | string | 出院诊断 |
| discharge_status | string | 出院情况 |
| chief_physician | string | 科主任 |
| deputy_chief_physician | string | 主副主任医师 |
| attending_physician | string | 主治医师 |
| resident_physician | string | 住院医师 |
| coder | string | 编码员 |
| operation_code | string | 手术编码 |
| operation_name | string | 手术名称 |
| operation_date | string | 手术日期 |
| surgeon | string | 术者 |
| first_assistant | string | 一助 |
| second_assistant | string | 二助 |
| anesthesia_method | string | 麻醉方式 |
| wound_healing_grade | string | 愈合等级 |
| is_danfou | string | 是否有单否项错误（有/无） |
| campus | string | 院区代码 |
| patient_status | string | 患者状态（在院/出院/空） |
| catalog_status | string | 编码状态（已编目/未编目/空） |

## 二、缺陷病历数下钻

**POST** `/defectCasesDrillDown`

在基础查询条件下，仅查询**有缺陷的病历**（在 case_quality 或 home_quality 表中存在记录），每个患者一条记录。

### 新增请求参数

| 参数名 | 类型 | 必填 | 说明 |
|--------|------|------|------|
| rule_id | array\|str | 否 | 缺陷编号，支持多选或逗号分隔 |
| rule_type | int\|str | 否 | 缺陷类型：`1` 代表病历，`2` 代表首页，配合 rule_id 使用 |

### 响应 list 字段

与「质控病历数下钻」**完全一致**。

---

## 三、缺陷数量下钻

**POST** `/defectCountDrillDown`

在基础查询条件下，以**缺陷为粒度**，一个患者可能出现多条记录（每条缺陷一行）。比前两个接口多出 `bl_type` 和 `notice` 两个字段。

### 新增请求参数

| 参数名 | 类型 | 必填 | 说明 |
|--------|------|------|------|
| rule_id | array\|str | 否 | 缺陷编号，支持多选或逗号分隔 |
| rule_type | int\|str | 否 | 缺陷类型：`1` 代表病历，`2` 代表首页，配合 rule_id 使用 |

### 响应 list 字段

包含前两个接口的全部字段，**额外新增**：

| 字段名 | 类型 | 说明 |
|--------|------|------|
| bl_type | string | 缺陷来源：`病历` 或 `首页` |
| notice | string | 缺陷描述 |

### 请求示例

```json
{

```

## 四、医师申诉情况

**POST** `/appealCasesDrillDown`

在基础查询条件下（注：其中`患者状态`、`编码状态`等均支持），查询**医师申诉情况**列表。排序规则：**未审核置顶（即审核状态为 0 待审核的记录在前），同状态下按出院时间倒序**。

### 新增请求参数

| 参数名 | 类型 | 必填 | 说明 |
|--------|------|------|------|
| appeal_status | array\|str | 否 | 审核状态：支持多选或逗号分隔，`待审核` (0)、`已通过` (1)、`未通过` (2)、`已整改` (3) |
| quality_type | array\|str | 否 | 质控类型：支持多选或逗号分隔，包含 `运行病历`、`运行首页`、`编码首页` |
| appeal_doctor | array\|str | 否 | 申诉医师：支持多选/逗号分隔，且支持模糊匹配 |
| defect_content | array\|str | 否 | 申诉问题：支持多选/逗号分隔，且支持模糊匹配 |
| case_doctor | array\|str | 否 | 质控审核医师：支持多选/逗号分隔，且支持模糊匹配 |
| reject_content | string | 否 | 通过/驳回原因：输入框模糊匹配 |
| appeal_time_start | string | 否 | 申诉时间起始，支持格式如基础参数，自动补全时分秒 |
| appeal_time_end | string | 否 | 申诉时间截止，支持格式如基础参数，自动补全时分秒 |
| examine_time_start| string | 否 | 审核时间起始，支持格式如基础参数，自动补全时分秒 |
| examine_time_end | string | 否 | 审核时间截止，支持格式如基础参数，自动补全时分秒 |

### 响应 list 字段

包含「质控病历数下钻」的全部基础患者字段（如姓名、年龄、科室、各项得分等），**额外新增**：

| 字段名 | 类型 | 说明 |
|--------|------|------|
| appeal_status_name | string | 审核状态（待审核、已通过、未通过、已整改） |
| quality_type_name | string | 质控类型（运行病历、运行首页、编码首页） |
| appeal_docter | string | 申诉医师 |
| defect_content | string | 申诉问题（缺陷描述） |
| appeal_time | string | 申诉时间，格式：YYYY-MM-DD HH:mm:ss |
| case_docter | string | 质控审核医师，格式：姓名（工号），例如：张三（101） |
| examine_time | string | 审核时间，格式：YYYY-MM-DD HH:mm:ss |
| reject_content | string | 通过/驳回原因 |
