# 企业微信质控预警通知模块说明

## 1. 模块目标

质控预警消息支持通过企业微信推送，提高消息提醒及时性。当前模块支持：

- 向指定企业微信用户发送预警消息，支持单人或多人。
- 向指定企业微信群发送预警消息，支持应用群聊或群机器人 webhook。
- 记录企业微信推送日志，包括发送时间、接收人、发送状态、失败原因、接口请求和响应。
- 通过企业微信任务卡片按钮记录“已收到/已查看”状态。
- 支持重复提醒策略配置，包括关闭重复提醒、固定时间重复推送、固定间隔重复推送。

> 注意：企业微信开放接口不能直接获取聊天窗口内真实已读状态。本模块采用“用户点击任务卡片按钮后系统标记已查看”的方式记录业务已读状态。

### 2.2 配置来源

企业微信配置不从 `.env` 读取，统一从数据库表读取：

```text
wechat_work_push_configs
```

配置项包括：

```text
corp_id              企业微信 CorpID
secret               应用 Secret
agent_id             应用 AgentId
access_token          手动维护 access_token，可为空
message_type          应用消息类型：text/taskcard
callback_url          企业微信应用回调 URL
callback_token        企业微信回调 Token
callback_aes_key      企业微信回调 EncodingAESKey
default_userids       默认接收人，逗号分隔
default_group_ids     默认群配置 ID，逗号分隔
repeat_enabled        是否开启重复提醒
repeat_type           fixed_times/interval
repeat_interval_minutes 固定间隔分钟数
repeat_times          固定推送时间，如 08:00,14:00,16:00,18:00
```

敏感配置不要写入代码仓库或文档。需要查看测试库当前明文配置时，可由有权限人员直接查询数据库。

## 3. 数据表说明

### 3.1 企业微信推送配置表

```text
wechat_work_push_configs
```

用途：维护企业微信应用配置、默认接收人、重复提醒策略和回调配置。

关键字段：

| 字段 | 说明 |
| --- | --- |
| enabled | 是否启用企业微信推送，1 启用，0 停用 |
| corp_id | 企业微信企业 ID |
| secret | 应用 Secret |
| agent_id | 应用 AgentId |
| message_type | 应用消息类型，建议使用 taskcard |
| callback_token | 企业微信回调 Token |
| callback_aes_key | 企业微信回调 EncodingAESKey |
| default_userids | 默认接收人企业微信 UserID，逗号分隔 |
| repeat_enabled | 是否开启重复提醒 |
| repeat_type | fixed_times 或 interval |
| repeat_times | 定时重复推送时间 |

### 3.2 企业微信群配置表

```text
wechat_work_groups
```

用途：维护可推送的企业微信群。

支持两种方式：

| send_type | 说明 | 需要配置 |
| --- | --- | --- |
| appchat | 企业微信应用群聊 | chat_id |
| webhook | 企业微信群机器人 | webhook_url 或 webhook_key |

### 3.3 企业微信推送日志表

```text
wechat_work_push_logs
```

用途：记录每一次企业微信推送。

关键字段：

| 字段 | 说明 |
| --- | --- |
| source_log_id | 原质控提醒日志 ID |
| warning_key | 同一患者、同一规则、同一问题的去重标识 |
| receiver_type | 接收类型，user/group |
| receiver_id | 企业微信 UserID 或群配置 ID |
| message_type | text/taskcard |
| task_id | 企业微信任务卡片 task_id |
| event_key | 任务卡片按钮 key，当前为 ack |
| send_status | 0 待发送，1 成功，2 失败，3 跳过 |
| send_time | 发送时间 |
| fail_reason | 失败原因 |
| read_status | 0 未查看，1 已查看 |
| read_at | 查看时间 |

### 3.4 企业微信预警已读记录表

```text
wechat_work_warning_reads
```

用途：记录用户点击“已收到”后的业务查看状态。

关键字段：

| 字段 | 说明 |
| --- | --- |
| warning_key | 预警去重标识 |
| source_log_id | 原质控提醒日志 ID |
| user_id | 系统用户 ID，无法识别时为 0 |
| wechat_userid | 点击按钮的企业微信 UserID |
| read_at | 查看时间 |

## 4. 接口说明

所有接口前缀：

```text
/api/wechat_work_notification
```

### 4.1 获取配置

```http
GET|POST /api/wechat_work_notification/config
```

返回企业微信推送配置和群配置。接口会对敏感字段做脱敏处理。

### 4.2 保存配置

```http
POST /api/wechat_work_notification/save_config
```

常用参数：

```json
{
  "enabled": 1,
  "message_type": "taskcard",
  "default_userids": "QuJianKun",
  "repeat_enabled": 0,
  "repeat_type": "fixed_times",
  "repeat_times": "08:00,14:00,16:00,18:00"
}
```

说明：请求未传的敏感字段会保留数据库原值，不会被清空。

### 4.3 保存群配置

```http
POST /api/wechat_work_notification/save_group
```

群机器人示例：

```json
{
  "name": "科室质控群",
  "send_type": "webhook",
  "webhook_url": "https://qyapi.weixin.qq.com/cgi-bin/webhook/send?key=xxxx",
  "enabled": 1,
  "remark": "科室质控群测试"
}
```

应用群聊示例：

```json
{
  "name": "医务科管理群",
  "send_type": "appchat",
  "chat_id": "企业微信应用群聊 chatid",
  "agent_id": "1000002",
  "enabled": 1
}
```

### 4.4 发送测试消息

```http
POST /api/wechat_work_notification/send_test
```

单人 taskcard 测试：

```json
{
  "title": "质控预警企业微信测试",
  "content": "请及时处理该质控预警。",
  "quality_content": "患者病程记录超过 24 小时未完成。\n请补充首次病程记录。",
  "basis": "住院病历书写规范要求：\n1. 首次病程记录应在规定时限内完成。\n2. 病程记录需体现诊疗过程。",
  "userids": ["QuJianKun"],
  "group_ids": []
}
```

当数据库配置 `message_type = taskcard` 且接收类型为 `user` 时，会发送任务卡片消息，用户点击“已收到”按钮后由企业微信回调系统更新已读状态。

字段说明：

| 字段 | 说明 |
| --- | --- |
| title | 企业微信消息标题 |
| content | 普通消息正文，测试消息中可作为兜底内容 |
| quality_content | 质控问题内容，优先显示为“问题” |
| problem | `quality_content` 的别名 |
| basis | 质控依据，优先显示为“依据” |
| msg_yj | `basis` 的别名 |
| userids | 指定企业微信接收人 UserID，支持数组 |
| group_ids | 指定企业微信群配置 ID，支持数组 |

换行说明：

- `quality_content`、`basis`、`content` 中可以使用 `\n` 换行。
- 服务会保留换行，只会压缩每一行内部多余空格和制表符。
- 如果未传 `basis` / `msg_yj`，不会再把与问题内容相同的 `content` 重复显示为依据。

群消息测试：

```json
{
  "title": "质控预警群推送测试",
  "content": "这是一条发送到企业微信群的测试消息。\n支持换行显示。",
  "userids": [],
  "group_ids": [1]
}
```

> 群机器人或 appchat 群消息不支持当前这种不打开页面的“已收到”按钮回调。若需要统计群内成员是否收到，建议额外给成员分别发送 taskcard。

### 4.5 手动推送指定质控预警

```http
POST /api/wechat_work_notification/send_warning
```

请求示例：

```json
{
  "log_id": 123,
  "force": 1,
  "userids": ["QuJianKun"],
  "group_ids": []
}
```

### 4.6 查询推送日志

```http
GET|POST /api/wechat_work_notification/log_list
```

请求示例：

```json
{
  "page": 1,
  "page_size": 20,
  "receiver_type": "user",
  "receiver_id": "QuJianKun"
}
```

已读筛选：

```json
{
  "read_status": 1
}
```

未读筛选：

```json
{
  "read_status": 0
}
```

### 4.7 链接兜底确认

```http
GET /api/wechat_work_notification/ack?log_id=1
```

该接口用于文本消息或无法使用按钮回调时的兜底确认，会打开一个简单页面并标记已查看。

### 4.8 企业微信应用回调

```http
GET|POST /api/wechat_work_notification/callback
```

用途：

- GET：企业微信后台保存回调配置时验证 URL。
- POST：接收任务卡片按钮点击事件。

该接口无需登录，不经过 `CheckLogin`。

## 5. 企业微信后台配置

按钮方式依赖企业微信应用回调。进入企业微信后台：

```text
应用管理
-> 自建应用
-> 找到 AgentId 对应应用
-> 接收消息 / 回调配置
```

填写：

```text
URL:
https://你的测试域名/api/wechat_work_notification/callback

Token:
从 wechat_work_push_configs.callback_token 获取

EncodingAESKey:
从 wechat_work_push_configs.callback_aes_key 获取
```

保存时企业微信会发起 GET 验证请求，本模块会完成签名校验和 AES 解密，并返回明文 `echostr`。

> 业务链接可以不做签名验证，但企业微信回调协议本身要求校验 `msg_signature` 并解密 `Encrypt`，否则无法获取按钮点击事件。

## 6. 测试流程

### 6.1 验证单人任务卡片发送

```bash
curl -X POST "https://你的测试域名/api/wechat_work_notification/send_test" \
  -H "Content-Type: application/json" \
  -H "token: 你的登录token" \
  -d '{
    "title": "质控预警企业微信测试",
    "content": "请及时处理该质控预警。",
    "quality_content": "患者病程记录超过 24 小时未完成。\n请补充首次病程记录。",
    "basis": "住院病历书写规范要求：\n1. 首次病程记录应在规定时限内完成。\n2. 病程记录需体现诊疗过程。",
    "userids": ["QuJianKun"],
    "group_ids": []
  }'
```

成功返回示例：

```json
{
  "code": 200,
  "msg": "企业微信推送处理完成",
  "data": {
    "success": 1,
    "fail": 0,
    "skip": 0
  }
}
```

企业微信内应显示任务卡片，并有：

```text
已收到
```

按钮。

任务卡片描述会保留换行，显示效果类似：

```text
问题：患者病程记录超过 24 小时未完成。
请补充首次病程记录。
依据：住院病历书写规范要求：
1. 首次病程记录应在规定时限内完成。
2. 病程记录需体现诊疗过程。
```

### 6.2 点击按钮后验证已读

点击企业微信卡片中的“已收到”按钮后，查询日志：

```bash
curl -X POST "https://你的测试域名/api/wechat_work_notification/log_list" \
  -H "Content-Type: application/json" \
  -H "token: 你的登录token" \
  -d '{
    "page": 1,
    "page_size": 10,
    "receiver_id": "QuJianKun"
  }'
```

应看到：

```text
message_type = taskcard
task_id      = wechat_work_push_log_xxx
event_key    = ack
read_status  = 1
read_at      = 点击时间
```

## 7. 重复提醒策略

### 7.1 关闭重复提醒

```text
repeat_enabled = 0
unchanged_skip_enabled = 1
```

同一患者、同一规则、同一问题未变化时，不再重复推送。

### 7.2 固定时间重复提醒

```text
repeat_enabled = 1
repeat_type = fixed_times
repeat_times = 08:00,14:00,16:00,18:00
```

在指定时间推送未处理问题。

### 7.3 固定间隔重复提醒

```text
repeat_enabled = 1
repeat_type = interval
repeat_interval_minutes = 120
```

每隔固定分钟数重复推送未处理问题。

## 8. 常见问题

### 8.1 返回 60020：not allow to access from your ip

原因：服务器出口 IP 未加入企业微信应用可信 IP。

处理：在企业微信后台自建应用里添加服务器出口 IP。

### 8.2 收到的是普通文本，不是卡片

检查：

```sql
SELECT message_type FROM wechat_work_push_configs;
```

应为：

```text
taskcard
```

同时确认线上代码包含：

```text
WechatWorkClientService::sendTaskCardToUsers()
QualityWechatWorkNotificationService::handleTaskCardClick()
WechatWorkNotificationController::callback()
```

### 8.3 点击“已收到”后状态没有更新

重点检查：

- 企业微信后台回调 URL 是否配置成功。
- Token 和 EncodingAESKey 是否与数据库一致。
- `/api/wechat_work_notification/callback` 是否公网可访问。
- 企业微信回调是否被网关、WAF 或登录中间件拦截。
- 推送日志中是否存在对应 `task_id`。

### 8.4 群消息能否用按钮确认

群机器人 webhook 不适合做这种按钮回调确认。若要记录“谁已收到”，应给目标人员分别发送 taskcard。

## 9. 正式接入建议

当前模块已具备接口测试能力。正式接入质控预警流程时建议：

1. 预警产生后先写入系统原有质控提醒日志。
2. 调用 `QualityWechatWorkNotificationService::pushQualityLog($logId)`。
3. 由 `wechat_work_push_logs` 记录每个接收人的发送和已读状态。
4. 对未处理且未读/未整改的问题，可结合重复提醒策略定时推送。
5. 群提醒用于广播，个人 taskcard 用于统计已收到状态。
